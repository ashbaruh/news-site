# מודל הנתונים — הסבר בעברית פשוטה

## הרעיון בשורה אחת

אירוע אחד יכול להיות מדווח ע"י כמה מקורות. **מספר המקורות לא אומר כלום** — מה שקובע זה **מכמה מקומות שונים באמת** המידע הגיע.

---

## ארבע טבלאות

### 1. אירועים (`events`)
"מה קרה". כל שורה = דבר אחד שקרה או נטען שקרה.

שדות שכדאי להכיר:

- **`occurred_at`** — מתי זה קרה, או מתי זה **התחיל**
- **`occurred_to`** — מתי זה הסתיים
- **`is_ongoing`** — האם זה עדיין נמשך
- **`first_reported_at`** — מתי דווח לראשונה
- **`last_update_at`** — מתי עודכן אצלנו לאחרונה

**למה כל כך הרבה תאריכים:**

1. בלי ההפרדה בין "מתי קרה" ל"מתי עודכן" אי אפשר להציג **אימות מאוחר** — אירוע שקרה לפני שלושה ימים ואומת רק היום (EV-015).
2. בלי `occurred_to` ו-`is_ongoing` אי אפשר לייצג **אירוע מתמשך** — וזה רוב מה שקורה במלחמות. "קרבות נמשכים מאז יום שלישי" אינו נקודה בזמן (EV-016), ו"גל תקיפות בן שלושה ימים" הוא טווח סגור (EV-017).

שלושת המצבים:

| מצב | איך זה נראה בנתונים | איך זה מוצג |
|---|---|---|
| נקודתי | `occurred_to` ריק, `is_ongoing` = false | "קרה: 16/09 04:20" |
| טווח סגור | `occurred_to` מלא | "11/09 20:00 ← 14/09 04:00" |
| עדיין נמשך | `occurred_to` ריק, `is_ongoing` = true | "מאז 14/09 06:00 · נמשך" |

- **`claim_type`** — איזה סוג טענה זו:
  - `incident` — אירוע שקרה
  - `statement` — הצהרה שמישהו אמר
  - `assessment` — הערכה או תחזית
  - `data` — נתון מדיד

  ההפרדה חשובה: "מאומת שהצהרה נמסרה" זה **לא** "מאומת שמה שנאמר בה נכון".

- **`lifecycle`** — מצב האירוע: `active` / `corrected` / `retracted` / `disputed`
- **`what_is_not_verified`** — טקסט חובה. הסעיף שהמפרט דורש במפורש.

### 2. מקורות (`sources`)
"מי דיווח". כל שורה = גוף מדווח אחד.

- **`license_mode`** — מה מותר לנו לעשות עם התוכן שלו. נקבע **ברגע חיבור המקור**, לא בדיעבד:

  | ערך | משמעות |
  |---|---|
  | `link_only` | כותרת מינימלית + קישור בלבד |
  | `summary_ok` | מותר סיכום בניסוח שלנו + קישור |
  | `licensed_data` | לפי תנאי ה-API |
  | `personal_only` | לא מוצג בגרסה הציבורית |
  | `unclear` | חסום מפרסום עד בדיקה |

- **`independence_group`** — "משפחת מקורות". שתי סוכנויות מדינתיות של אותה מדינה יושבות באותה משפחה, ולכן לא נספרות כשני אימותים עצמאיים.

### 3. דיווחים (`event_reports`)
זה הקישור: "מקור X דיווח על אירוע Y בשעה Z".

**כאן יושב השדה החשוב ביותר בכל הפרויקט:**

#### `source_root_id`

זה עונה על השאלה: **מאיפה הטענה באמת הגיעה במקור?**

לא "מי פרסם אותה", אלא "מה המקור-שורש": אותה תמונת לוויין, אותו סרטון, אותה הודעת דובר, אותו פוסט טלגרם.

**הכלל:** שני דיווחים עם אותו `source_root_id` = **אימות אחד**, לא שניים.

למה זה על שורת הדיווח ולא על המקור? כי אותו עיתון יכול לפרסם היום כתבה מבוססת מחקר עצמאי, ומחר לצטט פוסט טלגרם. השורש שייך לטענה, לא לגוף.

### 4. היסטוריית שינויים (`event_revisions`)
כל שינוי מוסיף שורה. **אף פעם לא דורסים.**

סוגי שינוי: `created` / `correction` / `retraction` / `status_change` / **`downgrade`** / `source_added` / `note`

בלי זה אי אפשר להציג "דווח 12, תוקן ל-3" — רק "3", וזה מסתיר מהקורא שהייתה טעות.

#### `downgrade` — כשהאימות מתבטל בדיעבד

זה הסוג החשוב ביותר, והוא זה שהכי קל לעשות בו את הטעות.

תרחיש: אירוע סומן "מאומת" על סמך שני מקורות. יומיים אחר כך מתברר ששניהם קיבלו את זה מאותו אדם.

**מה קורה בפועל:** מתקנים את `source_root_id` של שני הדיווחים לאותו ערך. זהו. הסטטוס **יורד מעצמו** בטעינה הבאה, כי הוא מחושב ולא שמור.

**אבל זה לא מספיק.** אם האתר פשוט יציג מעכשיו "לא מאומת" ויתנהג כאילו תמיד אמר את זה — זה שינוי בשקט, וזה בדיוק מה שהורס אמון.

לכן שורת `downgrade` מחזיקה גם `from_level` ו-`to_level`, והממשק **חייב** להציג באדום:

> ⚠️ אירוע זה הוצג באתר כ**מאומת** במשך כ-64 שעות, עד 16/09 08:10.

יש על זה גם אילוץ במסד הנתונים — אי אפשר לרשום `downgrade` בלי לציין מאיפה לאן.

ראה EV-018.

## איך מחושב הסטטוס

**סטטוס האימות אינו שדה במסד הנתונים.** הוא מחושב מחדש בכל פעם.

זה מכוון: אי אפשר "לסמן מאומת" ביד או בטעות. אם המקורות לא תומכים בזה, זה לא יופיע כמאומת.

הלוגיקה, לפי הסדר (`assets/js/reliability.js`):

```
1. האירוע בוטל?                      → "בוטל"
2. יש גרסאות סותרות?                 → "שנוי במחלוקת"
3. זו הערכה/תחזית?                   → "הערכה"
4. אין דיווחים בכלל?                 → "ללא מקור"
5. דיווח אחד בלבד?                   → "דיווח ראשוני"
6. כמה דיווחים, מקור-שורש אחד?       → "מקור-שורש משותף"  ← כאן ההגנה
7. שורשים שונים, אותה משפחת מקורות?  → "מקורות תלויים"
8. אחרת                              → "מאומת"
```

שלב 6 הוא הסיבה שהמודל הזה קיים. בלעדיו, EV-003 (פוסט טלגרם + אתר שמצטט אותו) היה נראה כמו "שני מקורות = מאומת". זה בדיוק סוג הטעות שהורס אמינות.

## 15 אירועי הדמה — מה כל אחד בודק

| קוד | מה הוא בודק | התוצאה שצריכה לצאת |
|---|---|---|
| EV-001 | מקור יחיד | דיווח ראשוני |
| **EV-002** | **2 מקורות עצמאיים באמת** | **מאומת** |
| **EV-003** | **2 מקורות, אחד מעתיק מהשני** | **מקור-שורש משותף** |
| EV-004 | דובר רשמי + סוכנות שמצטטת אותו | מקור-שורש משותף |
| **EV-005** | **תיקון בדיעבד (12 ← 3)** | **מאומת (תוקן)** + היסטוריה |
| **EV-006** | **מעבר מ"ראשוני" ל"מאומת"** | **מאומת** + 3 שורות היסטוריה |
| EV-007 | 2 סוכנויות של אותה מדינה, סיקור נפרד | מקורות תלויים |
| EV-008 | מקור עם רישוי לא ברור | המקור נשמר אך לא מוצג |
| EV-009 | דיווח שנמשך | בוטל |
| EV-010 | הערכה ולא דיווח | הערכה |
| EV-011 | לוויין + מכון מחקר | מאומת |
| EV-012 | 2 סוכנויות, הודעה רשמית אחת | מקור-שורש משותף |
| EV-013 | נתון שוק | נתון |
| EV-014 | שני צדדים סותרים | שנוי במחלוקת |
| EV-015 | אימות 3 ימים אחרי | מאומת + תג "אימות מאוחר" |
| **EV-016** | **אירוע שעדיין נמשך** | **מאומת + "נמשך כעת"** |
| EV-017 | אירוע בן 3 ימים שהסתיים | מאומת, מוצג כטווח זמן |
| **EV-018** | **אימות שבוטל בדיעבד** | **מקור-שורש משותף + "האימות בוטל"** |

חמשת המקרים המודגשים הם בדיוק אלה שהמפרט ביקש לבדוק בשלב 1.

**שים לב להבדל בין EV-003 ל-EV-007** — שניהם נראים כמו "שני מקורות", ושניהם נפסלים, אבל מסיבות שונות:

- **EV-003** — אותו מקור-שורש. אתר החדשות פשוט העתיק את פוסט הטלגרם.
- **EV-007** — שורשים שונים (כל סוכנות סיקרה בנפרד), אבל אותה משפחת מקורות. שתיהן סוכנויות מדינתיות של אותה מדינה.

זו הסיבה ששני השדות נחוצים ולא אחד. `source_root_id` תופס העתקה; `independence_group` תופס תלות מוסדית.

## מה המודל הזה **לא** עושה עדיין

המפרט דוחה את אלה במפורש, והמבנה הנוכחי לא חוסם אותם:

- רמת ביטחון נפרדת לכל שכבה במפה
- זיהוי אוטומטי של סתירות בין אירועים
- השוואת גרסאות זו מול זו בממשק
- ציר זמן חוצה-זירות

כולם ניתנים להוספה על גבי ארבע הטבלאות האלה בלי לשנות אותן.
